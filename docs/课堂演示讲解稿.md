# SuiEye 淬眸 · 课堂演示讲解稿

> 给老师讲这套系统时，按「先讲架构（1 分钟）→ 再讲一个模块的算法（3 分钟）→ 最后演示动线」的顺序最稳。
> 本文每个模块都按 **做什么 / 用什么技术 / 怎么实现（可指代码）/ 演示时说哪句话** 四段写。

---

## 一、一句话定位

一套**面向铅锌浮选车间的工业视觉 + 数据智能平台**：把摄像头拍到的泡沫图像，经过图像分割与特征提取，
用机器学习回归出精矿品位，再把品位异常放回「磨矿 → 浮选 → 回水」工艺链上找原因，
最后用 3D 数字孪生 + 实时告警的方式呈现给现场人员。

技术上有两个真正的骨架，其余都是围绕它们的应用：

1. **场景包（Scene Package）驱动** —— 一条 YAML 描述「输入 → 处理链 → 预测目标 → 告警规则」，后端按配置装配算法链，换场景只换 YAML。
2. **图像 → 特征 → 品位** 的可解释链路 —— 每一步的中间产物（分割边界、22 维特征、z-score）都留痕，能回查。

## 三、系统架构（讲解重点）

```
┌────────────────────────── 前端 Vue3（13 页）──────────────────────────┐
│ 3D 首页 · 直播墙 · 工作台 · 实时监控 · 仪表盘 · 报表 · 告警 · 安全 ·  │
│ 水质 · 尾矿 · 配药 · 时光机 · 设置                                     │
└───────────┬──────────────────────────────────┬───────────────────────┘
            │ REST /api/*（79 个）             │ WebSocket /ws/{channel}
┌───────────▼──────────────────────────────────▼───────────────────────┐
│                        FastAPI 路由层（13 个模块）                    │
├──────────────────────────────────────────────────────────────────────┤
│ 场景运行时 runtime.py                                                 │
│   读 scenes/{name}/{name}.yaml → 按 pipeline.filters 顺序执行          │
│   ↓ 引擎注册表 registry.py（name → Engine 实例，import 即注册）        │
│   roi_extract → enhance → segment → extract_features → predict        │
│                        ↓ 结果写回 EngineContext（含 trace 耗时）       │
│   alarm.py 按 YAML 的 alarm_rules 评估 → 写库 → WS 广播 → Webhook 派发 │
├──────────────────────────────────────────────────────────────────────┤
│ SQLAlchemy 模型层（22 张表：分析记录 / 告警 / 水质 / 尾矿 / 设备 …）   │
└──────────────────────────────────────────────────────────────────────┘
```

**为什么这样分层（可以讲的设计取舍）：**

- **算法层不碰 HTTP、不碰数据库**。`runtime.py` 的注释里明确写了「纯计算层」，入库由 API 层负责。
  好处是同一套算法可以被 API、脚本、离线批处理复用（`scripts/` 里就有批量导入、回填脚本）。
- **引擎注册表解耦**：YAML 里写 `name: segment`，注册表负责找到对应引擎；
  加载场景时就会校验引擎是否存在，配错在**启动期**报错而不是分析到一半崩。
- **上下文对象 `EngineContext` 串起整条链**：每个 filter 从 ctx 取输入、往 ctx 写输出，
  并 `add_trace(name, 毫秒, params)` —— 所以前端能看到「每一步各花了多少毫秒」。

**场景包 YAML 长什么样**（`backend/scenes/flotation/flotation.yaml`，节选）：

```yaml
pipeline:
  filters:
    - name: roi_extract      # 取中心 60% 区域
      params: { center_ratio: 0.6 }
    - name: enhance          # MSR + 双边滤波
      params: { method: msr_bilateral }
    - name: segment          # 分割（可换 watershed / felzenszwalb / unet / sam）
      params: { method: watershed }
    - name: extract_features # 22 维泡沫特征
      params: { feature_set: standard_11d }
    - name: predict          # 品位回归
      params: { model_key: xgb-v1 }

alarm_rules:
  - name: pb_too_low
    field: predicted.pb_grade_xrf   # 点路径，指向 ctx.prediction['pb_grade_xrf']
    condition: "<"
    threshold: 3.95
    level: warning
    cooldown_sec: 600
```

一句话：**换矿种、换工段，写 YAML 就行，不改代码**。这就是「场景包」的意义。

## 四、模块逐个讲

### 4.1 首页：智能工厂 3D 数字孪生

- **做什么**：一块可旋转/缩放/点击的厂区沙盘，10 台设备 + 5 个载体建筑都是功能入口，点进去就是对应功能页。
- **技术**：Three.js（WebGL）+ OrbitControls + Raycaster + CanvasTexture + 自定义 ShaderMaterial。
- **怎么实现**：
  - **没有外部模型文件**：厂房柱网、屋架、吊车梁（`utils/workshopStructures.js`）、设备（`utils/equipDetails.js`：法兰/护栏/铭牌/状态灯）全部用基础几何体拼出来。
  - 天空是**自定义着色器球体**（`createSkyDome`，天顶到地平线渐变），地面是 `CanvasTexture` 径向渐变（中心比设备暗一档，否则设备会"溶进地面"）。
  - 交互：`Raycaster` 做拾取，鼠标悬停高亮 + 标签浮出；相机切换用 `requestAnimationFrame` 自己做补间（避免 OrbitControls 把相机硬拉近）。
  - 性能：一个 `requestAnimationFrame` 主循环，卸载时 `cancelAnimationFrame` + dispose 释放几何体/材质。
- **演示时说**：「这不是加载的模型文件，是代码按厂房结构生成的 —— 所以它能随数据变（设备故障就变红），也不需要 3D 美术资源。」

### 4.2 实时监控

- **做什么**：左侧「现场画面」+ 画面内 HUD 实时品位，右侧品位趋势与 9 个测点的工艺链快照。
- **技术**：HTML5 `<video>` + ECharts 实时曲线 + 定时节拍（`BEAT_MS`）。
- **怎么实现**：画面来自**凡口铅锌矿 2019-08-22 的真实录像**，用 `scripts/transcode_replay_segments.py`（ffmpeg）把 23 段 AVI 转成 640×480 的 mp4，放 `frontend/public/media/froth2019/`，前端按段循环播放；数据按固定节拍推进，和画面对齐。
- **演示时说**：「视频是真的现场录像（脱敏后回放），数据节拍是我们模拟的采样周期 —— 工业现场摄像头一般 1~5 分钟采一帧，不可能真 30 帧/秒分析。」

### 4.3 分析工作台（**核心算法，最值得讲**）

一条完整的分析链，五个阶段，全部可回查：

| 阶段 | 做什么 | 算法 / 库 | 关键参数 |
|---|---|---|---|
| ① ROI 提取 | 裁掉图像边缘（泡沫池壁、反光） | 中心比例裁剪 | `center_ratio: 0.6` |
| ② 增强 | 抑制反光、拉开泡沫边界 | MSR（多尺度 Retinex）+ 双边滤波 | — |
| ③ 分割 | 把每个气泡单独标号 | 分水岭 / Felzenszwalb / U-Net / SAM | 阈值 0.5、最小面积 100px |
| ④ 特征 | 每张图提炼 22 维特征 | 自写 NumPy + OpenCV（GLCM 手写） | 灰度量化 16 级、4 方向 |
| ⑤ 预测 | 22 维特征 → 铅品位 % | XGBoost 回归（600 棵树） | 输出 clip 到 0.3~4.0 |

**分割的四条路线（老师一定会问"为什么用这个"）：**

| 方法 | 耗时 | 精度（注释里的实测） | 是否需要训练 | 结论 |
|---|---|---|---|---|
| 分水岭 Watershed | ~3 s | mIoU 60~68% | 否 | 可解释性最强，**当前演示默认** |
| Felzenszwalb 图分割 | ~250 ms | mIoU 65~72% | 否 | 快、边界好 |
| SAM（vit_b） | ~2 s | 对泡沫纹理过分割 | 零样本 | 通用模型不适配泡沫 |
| **U-Net（自写）** | 50 ms(GPU)/200 ms(CPU) | mIoU 85~92% | 是 | 精度最高，已实现并注册 |

> 讲这段时主动说清楚：**默认走分水岭**是因为现场没有足够的真实标注；U-Net 已经写好并接入
> （`backend/models/unet_foam.py` 281 行、权重 69MB、21 个 epoch、验证集 IoU 0.986），
> 但权重是在**程序合成的泡沫图**（Voronoi + Perlin 噪声）上预训练的，真实数据微调是下一步。
> 这也是为什么 `flotation.yaml` 里 CRF 边界精修被注释停用 —— 注释里写着"等真实数据微调 U-Net 后再评估"。
> **能讲清"哪一步还没做实"，比吹 85% 更得分。**

**22 维特征（可解释性的来源）**：

- 气泡几何 7 维：等效直径均值、尺寸标准差、圆度、圆度离散度、有效气泡数、尺寸偏度、峰度
- 纹理 7 维（GLCM 灰度共生矩阵，自己用 `np.roll` 实现 4 方向共现统计）：对比度、相关性、熵、能量、均匀性、逆差矩、方差
- 颜色 7 维：R/G/B 均值、灰度均值、相对红/绿/蓝（归一化掉光照）
- 计数 1 维：`n_foams` 气泡个数

**为什么这些特征能预测品位（选矿机理，老师会认这个）**：泡沫越小越密、纹理越丰富、颜色越亮（载矿多），
一般对应精矿品位越高。代码里的先验权重 `GRADE_WEIGHTS` 就是照这个写的：`bubble_avg_size` 是**负**权重、
`texture_entropy` 是**正**权重。

**预测的三级降级（工程上的可靠性设计）**：

```
XGBoost 真模型（data/model_pb_xgb_v1.json，3004 张真实图训练）
   ↓ 加载失败
model_config.json 里的线性回归 / 随机森林
   ↓ 也没有
手写权重启发式（选矿先验 + 物理区间归一化）
```

任何一级挂掉系统都能出结果，不会白屏 —— 这是「演示环境不一定装了 xgboost」的兜底。

### 4.4 告警中心（**工程亮点，建议重点讲**）

- **规则引擎**（`engines/alarm.py`）：规则写在场景包 YAML 里，`field` 是点路径（`predicted.*` / `features.*` / `metrics.*`），
  `condition` 映射到 `operator.lt/gt/...`。**任何场景包只要写规则就能告警，没有浮选专属代码。**
- **事件聚合**：`group_key` + 冷却时间，把同一设备同一规则的连续告警合成一个「事件」，避免刷屏。
- **根因联动归因**（`algorithms/root_cause.py`，714 行，最值得讲的一段）：
  以告警时刻为锚点，回溯三个工段的真实记录 ——
  磨矿的 P80 粒度、配药的药剂/PH/泡沫状态、回水的 pH/COD/SS/残留药剂，
  再用**时间衰减**（离告警越远权重越低）和**分层窗口**（窗口内=同期证据，7 天内=弱证据并标注距离）排序候选原因。
  代码里写了三条不可违背的原则：① 只用告警**之前**的信号，不用未来数据解释过去；② 信号缺失就写进 `missing`，不硬凑；③ 每个结论都带原始值、参照基线、时间距离、来源表，可回查。
- **实时推送**：FastAPI WebSocket 4 个频道（alarms / safety / equipment / water），事件契约统一 `{event, ts, data}`。
- **对外接入**：Webhook 适配飞书 / 企业微信 / 钉钉群机器人（`services/chat_adapters.py`）。
  这里有个真实的坑值得讲：三家签名算法**各不相同**（飞书 key 是 `ts\nsecret`、消息体为空；钉钉正相反），
  而且成功判定是 **HTTP 200 + body 业务码为 0** —— 只判 HTTP 200 会把"被对方拒收"记成"投递成功"。

### 4.5 报表 / 时光机（数据闭环）

- **报表**：按 7/30/90 天聚合，预测值 vs XRF 化验值对比曲线 —— 这是模型评估的入口。
- **时光机**：按时间回溯历史分析记录，把「相似工况」找出来对比（同粒度/同品位区间的历史片段）。
- **背后的概念（可以升维讲）**：数据飞轮 —— 现场化验台账（XRF）回流 → 与预测值配对 → 评估偏差 → 重新训练。
  库里有 `assay_ledger` / `courier_assays`（62798 条化验台账）就是为这个准备的。

### 4.6 工艺侧四个专业模块

| 模块 | 技术点 | 实现要点 |
|---|---|---|
| 水质监测 | 多指标评分 + 合规统计 | 5 个点位（pH/COD/SS/重金属/残留药剂），回水可回用性评分，GB 25466 排放标准比对 |
| 尾矿处理 | **软测量** + 机理前向推演 | 现场测不到底流浓度 → 用可测仪表变量回归出浓度 → 工况识别（正常/泥床过高/絮凝不足/跑浑/压耙）→ 搜索最优排放 setpoint 给建议 |
| 安全巡检 | YOLOv8 检测/分割 + 规则评估 | 人员、PPE 合规、皮带跑偏、异物；`assess_risk.py` 把检测结果折算成风险等级与工单 |
| 智能配药 | 领域专家知识库 | 捕收剂/抑制剂/起泡剂/调整剂四类，每种带基准用量与区间（如乙基黄药 60 g/t，30~120），按泡沫状态与品位推荐配方 |

## 七、老师可能追问的 10 个问题（含诚实答法）

1. **"品位预测的准确率多少？"**
   → 不报单一数字。讲口径：XGBoost 用 3004 张真实图训练、7 维特征、600 棵树；评估要看「预测 vs XRF 化验」的偏差分布，
   报表页那条对比曲线就是干这个的。同时承认：**当前演示库里的 Pb 均值在 5.1% 左右，是项目定的展示口径（3~8%）**，不是全矿标定结果。
2. **"为什么不用端到端 CNN 直接回归品位？"**
   → 三个原因：样本量不够（几千张）、不可解释（现场要问"为什么低"）、标注贵（品位要靠化验）。
   特征 + XGBoost 的好处是每一步可回查、可 z-score 体检、样本效率高。端到端是后续数据够了的方向。
3. **"分割精度 85~92% 怎么来的？"**
   → 老实说：那是**合成数据**上的验证集 IoU（0.986），真实图上的 mIoU 还没系统评测。
   现场默认用分水岭（mIoU 60~68%），因为没标注。**这条一定要主动说，被追问出来更难看。**
4. **"锌品位怎么预测的？"**
   → 目前是**由铅品位按 0.48~0.72 的比例关系推导**（铅锌共生），不是独立模型。这是一个已知简化，
   多任务回归是下一步。
5. **"数据是真的吗？"**
   → 分三层说清楚：① 泡沫/磨矿/安全图像是真实现场数据；② 实时监控视频是 2019-08-22 的真实录像回放；
   ③ 尾矿/水质的时间序列是**机理仿真**生成（物理公式驱动，不是随机数）。演示时不要含糊。
6. **"根因分析是不是 LLM 编的？"**
   → 不是。是规则 + 统计：工艺先验（过磨泥化、pH 抑制失效、捕收剂不足、回水残留干扰）+ 时间衰减加权 + 分层窗口，
   每个结论都带原始值与来源表，可以点开回查。
7. **"为什么用 SQLite？"**
   → 零部署、评委拷走就能跑。ORM 层用 SQLAlchemy，JSON 字段在 PostgreSQL 下自动映射成 JSONB，换库只改连接串。
8. **"3D 是不是用 Blender 做的模型？"**
   → 不是，全部代码生成（几何体 + 自定义着色器），所以能跟数据联动、体积小。
9. **"实时性怎么保证？"**
   → WebSocket 推送（不是轮询）；分析链每步有 trace 耗时，可以现场看哪一步慢。
10. **"这套东西能落地吗？缺什么？"**
    → 缺三样：真实标注数据（分割 + 化验配对）、与 DCS/PLC 的接口、现场网络与算力。
    代码里已经留好了位置：场景包换 YAML、模型换权重文件、告警接 Webhook。

## 九、答辩时的三条原则

1. **先讲"为什么这么设计"，再讲"用了什么技术"** —— 老师更关心取舍，不是库的名字。
2. **主动交代边界**：哪部分是真模型、哪部分是仿真、哪部分是展示口径。工业项目里"数据从哪来"是第一个被问的。
3. **每讲一个模块，落回一个现场痛点**：品位靠人工看泡沫 → 主观且滞后；告警只报"哪里不对"不报"为什么" → 处置慢。
