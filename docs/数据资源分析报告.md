## 二、逐项解析

### 1️⃣ 锌矿品位预测数据集（现有数据的"完全体"）

```
锌矿品位预测数据集/
├── allpictures/        3004 张泡沫图（= znkc_catalog 图片源，4 图/品位值）
├── alllabels/          642 个 Courier 在线分析仪 20min 报告（.xls）
├── features.xls        3004 行 × 18 维特征
├── labels.xlsx         750 行 × 3 列品位值
└── 拼合数据集/My_dataset.xls   3004 行 × (18特征 + 标签)
```

**关键发现：**

- **化验报告来自 Courier 在线分析仪，Plant = fankou（凡口铅锌矿）**。报告含 3 条采样线 × 3 种金属（Fe/Zn/Pb）：
  - `H pb-zn II`：混合流（Zn≈31%，Pb≈12%）
  - `Kpb II`：铅回路（Pb≈56%，Zn≈2.6%）
  - `Kzn II`：锌回路（Zn≈54%，Pb≈0.7%）
  每条流都有 计数/最小/最大/平均/最后值 五档统计 + 逐条记录（50 行 × 29 列/报告）。
- **`labels.xlsx` 有 3 列品位，现有系统只用了第 2 列**（My_dataset 标签 = 第 2 列，如 1.33342）。第 1 列（≈27.3）和第 3 列（≈0.44）从未进入模型。具体流别对应关系可结合 642 份原始报告进一步考证。
- **特征表 18 维 vs 现用 7 维**：多出 陡峭度、偏斜度、G/B 均值、色调均值、灰度均值、相对 RGB 分量、承载率（负载量）等 11 维——特征升级即插即用。
- `readme.txt` 明确：**前 80 帧有图、6 帧起无速度/稳定性特征**——做时序特征（泡沫速度、稳定性）时注意边界。

**对平台的价值：**
- 特征层 7 维 → 18 维，直接喂 XGBoost 重训即可能提升精度；
- 多目标品位（3 列）→ 品位预测从单值升级为多金属同时预测；
- 642 份原始报告 → `assay_ledger` 化验台账的真值金矿（现在台账表是空的）。

### 2️⃣ I3E：泡沫性能分类数据集

```
I3E/
├── class Ⅰ/   472 张    优
├── class Ⅱ/   505 张    良
├── class Ⅲ/   339 张    中
├── class Ⅳ/   405 张    差
└── Froth flotation performance data-dataset 4.xls   20498 行 × 20 列特征序列
```

1721 张**按浮选性能优劣分级**的泡沫图 + 对应时间段的长特征序列（15+ 维数值特征，时间间隔约 2 分钟）。

**对平台的价值：这是"泡沫状态诊断引擎"的现成训练集。** 在直播墙/工作台上加一个"工况打分"能力：上传泡沫图 → 分类器输出 Ⅰ~Ⅳ 级 → 与品位预测互相印证。经典机器学习（SVM/随机森林/XGBoost 多分类）即可起步，无需深度学习。

### 3️⃣ seg：分割训练资源（含完整训练代码）

```
seg/
├── froth image/   18 张（按帧内偏移裁切的局部图）
├── seg mask/      14 张（一一对应的 _mask 标注）
└── train.py       ~640 行 PyTorch 训练脚本
```

`train.py` 是个**工业级边界感知分割训练脚本**，比预想的成熟得多：

- 基于 `segmentation_models_pytorch`（SMP），多骨干可选；
- **边界感知**：线标注 → 边缘掩码 + 软边界（距离变换 + 高斯）；
- **半监督学习（SSL）**：EMA teacher-student、一致性正则、多种 SSL 变体；
- 损失：Dice + 边缘加权 BCE；数据增强：几何（mask 用最近邻插值）+ 光度 + 高斯噪声；
- CLI 完整、带预览导出。

**对平台的价值：分割引擎的升级路线图。** 现有 `algorithms/` 用经典图像分割（分水岭），Phase 2 之后可以用这份脚本训练深度模型替换——`engines/` 架构天生支持"多算法引擎竞争上岗"，经典和 DL 各做一个 Engine，用 18 张标注图 + SSL 扩增。

### 4️⃣ binocular：2022 年双目相机数据（最大的新资产）

```
binocular/
├── 0902-0909/                  2022-09-02 ~ 09-09（未标定）
│   ├── L/   179 个时间戳文件夹 × ~59 帧
│   └── R/   576 个时间戳文件夹 × ~59 帧
├── cali_after_250_L/           2022-09-26 ~ 09-29（标定后）366 个时间戳 × ~59 帧
├── cali_after_250_R/           同上 366 个
├── znkcx_pbx0902-0909.xlsx     576 行
└── znkcx_pbx.xlsx              366 行（09-26~29）
```

- **两份品位表结构相同**：`time, znkcx_zn, znkcx_pb, znkxc_solid, pbx_zn, pbx_pb, pbx_solid`
  - `znkcx`（锌矿粗选/槽内）：Zn≈2.4~3.0%，Pb≈0.5%，固含≈25%
  - `pbx`（泡沫精矿相）：Zn≈7.5%，Pb≈0.6~0.8%，固含≈37~39%
- 帧号 25~1475，单帧约 40 KB，每个时间戳采约 59 帧（视频段抽帧）；
- 时间戳与品位表**逐行对齐**（如 `0926095625` ↔ `2022-09-26 09:56` 附近）；
- 注意：0902-0909 时段 **L 目残缺**（179/576），R 目完整；cali 时段双目齐全。

**对平台的价值：三重。**
1. **数据更新**：比现有 2020 数据新两年，模型时效性验证/再训练的理想素材；
2. **多目标**：6 个回归目标（两流 × Zn/Pb/固含），比现有单品位丰富一个量级；
3. **双目立体视觉**：左右目 → 泡沫三维形貌（高度场、流速场、崩塌动态）——单目给不了的特征维度，这正是 README 里说的"速度和稳定性"特征的正确打开方式。

## 四、对平台路线图的影响（建议）

原规划 Phase 2（引擎核心）优先级不变，但这包数据带来三个**高性价比插入项**：

| 插入项 | 动作 | 成本 | 收益 |
|---|---|---|---|
| **A. 特征升级** | Filter 特征 7 维 → 18 维，XGBoost 重训对比 | 低（半天） | 预测精度可能直接提升 |
| **B. 化验台账填充** | 解析 642 份 Courier 报告 → `assay_ledger` | 低（半天） | 时光机/模型体检页立刻有真值数据流 |
| **C. 工况分类引擎** | 用 I3E 1721 张图训 4 分类器，新增第二个 Engine | 中（1 天） | 直播墙增加"工况打分"卡片，卖点功能 |
| D. DL 分割引擎 | 用 seg 资源 + train.py 训练深度分割 | 高 | 分割质量升级，放 Phase 3 |
| E. 双目场景包 | binocular 数据建第二场景包（立体视觉） | 高 | 放 Phase 4/5，作为平台多场景能力的实证 |

**推荐执行顺序：Phase 2（原计划）→ A + B（顺手升级）→ C → Phase 3 → D → E。**

## 五、风险与注意点

1. **磁盘**：这包数据 + 重复压缩包共 ~13G；suieye-platform 引用时建议做软链或按需拷贝，不要整包复制；
2. **L 目残缺**：0902-0909 时段左目只有 179/576，双目立体特征只能在该时段的子集上做；
3. **labels 列语义**：3 列品位中第 1、3 列的流别对应关系未最终考证（需对时间戳抽样比对 Courier 报告）；
4. **Excel 日期坑**：I3E 特征表的时间列被解析成 `3920-09-09`（年份溢出），实际是 2020，导入时需修正；
5. **train.py 依赖**：torch + segmentation_models_pytorch，托管 venv 目前未装，启用 D 项时再装。
