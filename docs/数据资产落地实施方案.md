## 功能 A：特征 7 维 → 18 维 + 模型重训（半天）

### 现状诊断

**当前 XGBoost 只吃 7 个特征**（`predictor.py:13-21`）：

```python
XGB_FEATURES = [
    "bubble_avg_size",    # 1.平均尺寸
    "bubble_size_std",    # 2.标准差
    "texture_contrast",   # 5.对比度
    "texture_correlation",# 6.相关性
    "texture_entropy",    # 7.熵
    "texture_energy",     # 9.能量
    "r_mean",             # 10.R均值

```

**但 `extract_features()` 已经提取了 21 维！** 其中 14 维与数据集的 18 维能直接对上，只是没喂给模型。

### 具体改动

#### 改动 1：`backend/algorithms/features.py` —— 新增 2 个特征提取

在 `extract_features()` 函数末尾、return 之前加入：

```python
# 新增：13. 色调均值（HSV 的 H 通道）
hsv = cv2.cvtColor(cropped_bgr, cv2.COLOR_BGR2HSV)
hue_mean = float(hsv[:, :, 0].mean())

# 新增：18. 承载率（泡沫前景面积占比，即 froth loading）
if fg_mask is not None:
    loading_rate = float(fg_mask.sum() / fg_mask.size)
else:
    # 无掩码时用灰度阈值估算前景占比
    _, thresh = cv2.threshold(gray_full, 0, 255, cv2.THRESH_OTSU)
    loading_rate = float(thresh.sum() / thresh.size)

features["hue_mean"] = hue_mean
features["loading_rate"] = loading_rate
```

**工作量**：约 10 行代码。

#### 改动 2：`backend/algorithms/predictor.py` —— 扩展 XGB_FEATURES 到 18 维

```python
XGB_FEATURES = [
    "bubble_avg_size",      # 1.平均尺寸
    "bubble_size_std",      # 2.标准差
    "bubble_size_kurtosis", # 3.陡峭度（新增）
    "bubble_size_skew",     # 4.偏斜度（新增）
    "texture_contrast",     # 5.对比度
    "texture_correlation",  # 6.相关性
    "texture_entropy",      # 7.熵
    "texture_uniformity",   # 8.均匀度（新增）
    "texture_energy",       # 9.能量
    "r_mean",               # 10.R均值
    "g_mean",               # 11.G均值（新增）
    "b_mean",               # 12.B均值（新增）
    "hue_mean",             # 13.色调均值（新增）
    "gray_mean",            # 14.灰度均值（新增）
    "relative_red",         # 15.相对红色（新增）
    "relative_green",       # 16.相对绿色（新增）
    "relative_blue",        # 17.相对蓝色（新增）
    "loading_rate",         # 18.承载率（新增）
]
```

**注意**：改完这行后**旧模型不能直接用**——旧模型只认 7 维输入，新代码会传 18 维导致维度不匹配。必须同步重训模型（见下）。

#### 改动 3：用 `features.xls` + `labels.xlsx` 重训 XGBoost

写一个训练脚本 `scripts/retrain_xgb_18d.py`：

1. 读 `锌矿品位预测数据集/features.xls`（3004 行 × 18 列）→ X
2. 读 `锌矿品位预测数据集/labels.xlsx`（750 行 × 3 列）→ y（取第 2 列作为 pb_grade，或三列全训）
3. 列名映射：`1平均尺寸→bubble_avg_size`, `2标准差→bubble_size_std`, ……
4. `xgboost.XGBRegressor().fit(X, y)` → 保存为 `data/model_pb_xgb_v2.json`
5. 输出交叉验证 R² / MAE 与旧模型对比

**预期收益**：多 11 个信息维度进入模型，R² 从当前水平大概率提升。即使提升不大，也为后续多目标预测打下基础。

#### 改动 4：场景包 YAML 升级

`flotation.yaml` 的 `pipeline.filters.extract_features.params.feature_set` 从 `standard_11d` 改为 `full_18d`；`prediction_targets` 补齐第 3 个目标（solid_concentration）。

## 功能 B：多目标预测——从单品位到 Zn/Pb/固含三目标（1 天）

### 数据基础

`labels.xlsx` 有 **3 列**（750 行），`My_dataset.xls` 标签只用第 2 列：

| 列 | 值域（抽样） | 推测含义 |
|---|---|---|
| 第 1 列 | ~27.3 | 锌粗选 Zn 品位？（或混合流总金属） |
| 第 2 列 | ~1.33 | 铅精矿 Pb 品位（= 当前模型目标）✅ |
| 第 3 列 | ~0.44 | 固含浓度？或次要金属 |

**需要做的**：抽样比对 642 份 Courier 报告的时间戳，确认 3 列分别对应哪条采样线/哪种金属。报告里已看到：
- `Kpb II`（铅回路）：Pb≈56%, Zn≈2.6%
- `Kzn II`（锌回路）：Zn≈54%, Pb≈0.7%
- `H pb-zn II`（混合流）：Zn≈31%, Pb≈12%

### 架构改动

```
predictor.py
├── XGB_FEATURES          → 不变（18 维共享）
├── _predict_xgb()        → 改为返回 dict {"pb_grade": x, "zn_grade": y, "solid": z}
├── model_pb_xgb_v2.json  → Pb 品位模型（已有）
├── model_zn_xgb_v1.json  → 新增：Zn 品位模型
└── model_solid_xgb_v1.json → 新增：固含浓度模型

flotation.yaml
└── prediction_targets     → 从 2 个扩展到 3 个（pb_grade / zn_grade / solid_concentration）

frontend/
├── Workbench.vue          → 结果卡片从 1 个数值变为 3 个（Pb/Zn/固含）
└── LiveWall.vue           → 浮选节点显示多目标趋势
```

**核心改动点**：`predictor.py` 的 `_predict_xgb()` 加一个 `target` 参数，加载不同模型文件即可。三个模型共享同一套 18 维特征，训练脚本循环三次。

## 功能 C：化验台账自动填充（半天）

### 数据基础

`alllabels/` 下有 **642 份 Courier 在线分析仪 20min 报告**（`.xls`），每份含：

- 工厂：**凡口铅锌矿（fankou）**
- 3 条采样线 × 3 种金属（Fe/Zn/Pb）= 9 个通道
- 每通道：计数 / 最小 / 最大 / 平均 / 最后值 + 逐条记录（时间戳精确到秒）
- 时间窗口：2020-09-09 ~ 09-18（与图像数据同周期）

### 映射到现有数据库

`assay_ledger` 表结构（已在 `database.py` 定义）：

| 表字段 | Courier 报告对应字段 | 来源 |
|---|---|---|
| `scene_name` | 固定 `"flotation"` | — |
| `sample_time` | 报告内每行的 timestamp | 报告行数据 |
| `stream_id` | `H pb-zn II` / `Kpb II` / `Kzn II` | 报告头 |
| `metal` | `Fe` / `Zn` / `Pb` | 报告头 |
| `value` | 该行该通道的测量值 | 报告行数据 |
| `unit` | `%`（品位）/ 未知（浓度） | 固定 |
| `source` | `"courier_xrf_fankou"` | 固定 |
| `raw_report_file` | 文件名如 `II 20min report_200909_1000.xls` | 文件名 |

### 具体动作

写 `scripts/import_assay_reports.py`：

1. 遍历 `alllabels/*.xls`
2. 用 `pandas` 解析每份报告（跳过前 8 行表头，从第 10 行开始读数据）
3. 提取 3 条采样线 × 3 种金属 = 每份最多 9 条记录写入 `assay_ledger`
4. 预计入库 **5000+ 条化验记录**

**平台受益页面**：
- **时光机（TimeMachine.vue）**：选择时间段后，除了预测曲线还能叠加显示 Courier 真实化验值——这是模型校准的金标准
- **模型体检（ModelProfile.vue）**：预测值 vs 化验真值的偏差分布图有了真实数据源
- **告警系统**：当预测值与最近一次化验值偏差 > 阈值时触发"模型漂移"告警

### 架构定位：第二个 Engine

按平台 `engines/` 设计意图，这不改现有浮选引擎，而是**新建一个分类引擎**：

```
backend/engines/
├── __init__.py
├── flotation_engine.py      （现有，回归引擎，Phase 2 完善）
└── condition_classifier.py  （新建，分类引擎，本功能）
```

### 实现方案（两阶段）

**阶段 1：经典 ML 分类器（1 天可交付）**

1. 用 `Froth flotation performance data-dataset 4.xls` 的 20498 行特征 + 图片对应的 class 标签（通过时间戳关联）训练
2. 算法选型：`RandomForestClassifier` 或 `XGBClassifier`（4 分类）
3. 输入：现有的 18 维特征（与回归引擎共享）
4. 输出：`{"class": 2, "label": "良", "confidence": 0.87}`

**阶段 2：CNN 图像分类（可选升级）**

1. 用 1721 张原图直接训练 ResNet/EfficientNet 微调
2. 输入：原始泡沫图（不经特征提取）
3. 优点：捕捉纯视觉模式（颜色分布、泡沫排列拓扑）可能优于手工特征

## 功能 E：DL 分割引擎升级（Phase 3，2~3 天）

### 数据基础

```
seg/
├── froth image/   18 张（局部裁切图）
├── seg mask/      14 张（一一对应的边缘掩码 _mask.jpg）
└── train.py       ~640 行工业级 PyTorch 训练脚本
```

`train.py` 是个**成熟度很高的训练框架**：

- 基于 `segmentation_models_pytorch`（支持 UNet/FPN/DeepLabV3+/MANet 等多骨干）
- **边界感知分割**：线标注 → 边缘掩码 + 软边界（距离变换 + 高斯加权）
- **半监督学习（SSL）**：EMA Teacher-Student、一致性正则化、多种 SSL 变体
- 完整的数据增强管线（几何 + 光度 + 噪声）、Dice + 边缘加权 BCE 损失
- CLI 参数完整、带预览导出

### 与现有平台的衔接

```
当前分割（pipeline 的 segment filter）:
  method: watershed  →  经典分水岭（fast 但粗糙）

DL 分割引擎（新建）:
  backend/engines/dl_segmenter.py
  └── 加载 train.py 训练出的 SMP 模型
  └── 输出: 二值掩码（与 watershed 输出格式一致，即插即用）

flotation.yaml 切换:
  pipeline.filters.segment.params.method: watershed → dl_unet
```

### 执行路线

1. **环境准备**：venv 装 `torch` + `segmentation_models_pytorch`（~2GB 磁盘）
2. **数据准备**：seg 目录只有 18/14 对，先用这些跑通流程验证；后续可用平台积累的分析记录（带分割结果）做自标注扩充
3. **训练**：`python seg/train.py --encoder resnet34 --epochs 50 --batch-size 4`
4. **集成**：新建 `dl_segmenter.py` Engine，加载 `.pth` 权重，输出掩码
5. **A/B 对比**：工作台页同时展示 watershed 和 DL 两种分割结果，用户可切换

> **建议放 Phase 3**：因为需要 GPU/大量显存，且 18 张标注图偏少（SSL 可以缓解但效果上限受限于标注量）。先让 Phase 2 的经典引擎跑通，DL 作为精度升级选项。

### 6 个回归目标（vs 现有 1 个）

| 目标 | 含义 | 值域 | 现有平台 |
|---|---|---|---|
| znkcx_zn | 锌粗选槽 Zn 品位 | 1.4%~3.0% | ❌ |
| znkcx_pb | 锌粗选槽 Pb 品位 | 0.48%~0.82% | ❌ |
| znkxc_solid | 锌粗选固含浓度 | 25%~27% | ❌ |
| pbx_zn | 泡沫精矿相 Zn | 6.4%~7.7% | ❌ |
| pbx_pb | 泡沫精矿相 Pb | 0.52%~0.86% | ❌ |
| pbx_solid | 泡沫精矿相固含 | 37%~40% | ❌ |

### 立体视觉能带来的新特征（单目做不到的）

| 新特征 | 含义 | 实现方式 |
|---|---|---|
| **视差图（Disparity Map）** | 左右目像素偏移 → 泡沫深度场 | SGM/StereoSGBM |
| **泡沫高度分布** | 从视差图反算 3D 高度 | Q矩阵 + 三角化 |
| **流速场（Optical Flow）** | 同一目标在左右目的位置差 → 运动向量 | Lucas-Kanade / RAFT |
| **泡沫稳定性指标** | 连续帧间高度变化方差 | 时序分析 |

这正是 README 里说的**"前 80 帧有图、6 帧起无速度和稳定性特征"**的正确打开方式——双目给了你速度和稳定性。
