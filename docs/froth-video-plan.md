## 3. 开源同类调研（业界怎么做）

| 项目 / 论文 | 做法 | 我们能拿什么 |
|---|---|---|
| `gbellandi/bubble_size_analysis` (BSA) | 把"哪些处理步骤组合有效"固化成**可复用 pipeline**（Canny / 自适应阈值两套）；强调**分割后按形状过滤才是关键**（用 circularity 倒数 + convexity 剔除"不是气泡的东西"） | ★ 照搬「先分割、再按形状过滤」的两段式，而不是一步阈值了事 |
| `fravij99/Foam_Segmentation` | 梯度 + 分形双路分割；**盒计数法算分形维数**；气泡直径分布拟合 scaling exponent | 分形维数 → 比现有 `texture_energy` 更有物理意义的"泡沫纹理复杂度" |
| `toastytato/BubbleCV` | 多线程逐帧 + **跨帧跟踪气泡位置** + **气泡寿命分析** | 泡沫流速可以从"逐气泡跟踪"降级为**稠密光流均值**，省一个量级的算力 |
| `ywflow/BubMask` | Mask R-CNN 气泡实例分割（有预训练权重） | ❌ 太重，demo 不用 |
| 《Minerals》2022 · Zhang et al. | **Retinex 光照补偿（区域自适应 + 多尺度）** 解决光照不均/阴影 → 再跑改进 watershed；分割精度 +3.3%、耗时 −9.9% | ★★ 现场视频必然光照不均，**不做补偿直接阈值必挂** —— 这大概率就是那 3006 张失败的同类原因 |
| 《Measurement》2019 · Zhang et al. | **marker-based watershed：marker 取气泡内部的"高光白点"**；并指出**铅锌浮选中大/中气泡上的杂质灰度与小气泡相似**，导致误分 | ★★ 我们的视频里**高光白点非常明显**（见联系表），可直接做 marker；这条也**正面解释了**历史数据为什么分割失败 |
| UCT · Gordon 博士论文 | h-dome 提 marker + watershed；算 Sauter 平均直径 d32、圆形度、椭圆度 | 指标定义直接引用，不用自己发明 |

**结论**：铅锌浮选泡沫分割在学术上是有共识路径的 ——
**Retinex 补偿 → 高光点做 marker → watershed → 按形状过滤**。我们不需要发明算法，照这条链走即可。

## 4. 技术方案（全部已实测）

### 4.1 转码

本机**没有 ffmpeg**。解法：pip 装 `imageio-ffmpeg` 到隔离 venv（自带 ffmpeg 7.1 静态版，含 libx264 / libvpx-vp9 / libwebp）。已验证可用。

```bash
ffmpeg -i 动态.avi -vf "fps=25,scale=692:-2" \
       -c:v libx264 -preset veryfast -crf 30 \
       -pix_fmt yuv420p -movflags +faststart out.mp4
```

| CRF | 全片外推体积 | 画质 |
|---|---|---|
| 26 | 5.5 MB | 高 |
| **30** | **3.7 MB** | **推荐**（31× 压缩，泡沫纹理看不出损失） |
| 33 | 2.7 MB | 够用，细节略糊 |

- **80fps → 25fps 是关键一步**：体积 ÷3.2，泡沫运动本来就慢，肉眼无差
- 转码耗时 ~3 秒（veryfast）

### 4.2 浏览器可播性（实测）

```
readyState=4 · 692×518 · duration=8 · paused=false · error=null
currentTime 3.02 → 5.02（正常推进）
canPlayType('video/mp4; codecs="avc1.640028"') = "probably"
```
**通过。** 证据文件：`outputs/_froth_probe/clip8s_crf30.mp4`

### 4.3 载体选择

| 用途 | 载体 | 理由 |
|---|---|---|
| 2D 平面画面（直播墙） | `<video>` + MP4 | 走浏览器硬件解码，CPU 最低；可暂停 / 可 seek |
| 3D 泡沫贴图 | **同一个 `<video>` 元素** → `THREE.VideoTexture` | 复用同一个解码器，省一份解码；比图像序列省约 10 倍体积 |

> 不要为一台设备单独建一个 video 元素。浮选槽有 2 台，**共用同一个视频源**（用 `currentTime` 偏移区分，见坑 11）。

### 4.4 无缝循环（必须处理）

首末帧差 35.7/255，直接 `loop` 会"啪"地跳一下。三个方案：

1. ★ **生成交叉淡化衔接段**（约 1.2s）：取尾 1.2s 与头 1.2s 做 alpha 融合，追加到尾部 → 循环点肉眼不可见。**推荐**，用 ffmpeg `xfade` 一次生成
2. **乒乓播放**（正放 + 倒放）：绝对无跳变，但泡沫"倒流"违反物理，内行一眼看出假
3. **随机起播点**：看不出循环，但截图/录屏不可控

## 5. 已知坑（这些是"像不像真的"的分水岭）

1. **染色与配色归一**：`polishMaterials` 只处理 `MeshStandardMaterial`、`applyTwinTint` 只处理带 `emissive` 的材质。
   → **泡沫贴图用 `MeshBasicMaterial` 就天然免疫**（视频纹理本来也不需要打光）。
   → 若为了让泡沫接受光照/投影改用 `MeshStandardMaterial`，**必须把 mesh.name 加进 `SKIP_TINT`**，否则会被 lerp 0.66 染成一块钢蓝灰板子。
2. **`texture.colorSpace = THREE.SRGBColorSpace`** —— 漏了颜色会发灰发闷。
3. **`muted + autoplay + playsinline`** 三个属性缺一不可，否则浏览器直接拦掉自动播放。
4. **`minFilter = LinearFilter`、关 mipmap** —— 视频纹理每帧都在变，生成 mipmap 是纯浪费。
5. **停机联动**：设备 `stopped` → `video.pause()`。跟刚做完的"停机暂停旋转部件"是**同一套语义**，实现也走同一个分支最自然。
6. **平铺接缝**：槽顶 2.62×2.62 是方形、视频 692×518 是 4:3。要么裁成正方形（推荐，取中间无强特征的区域），要么 `RepeatWrapping` 平铺（会露接缝）。
7. **首帧封面**：加 `poster` 静帧，避免加载瞬间白屏 / 黑屏。
8. **素材放 `frontend/public/media/`** —— Vite 原样拷贝，不打进 bundle，不增大构建产物。
9. **AVI 头里的 80fps 可能是假的** —— 解码器读出来也是 80，但以实际解码结果为准（转码时 `fps=25` 会强制重采样）。
10. **`preload="auto"`** —— demo 现场必须秒开，不能等用户点播放。
11. ★ **两台浮选槽共用同一视频会"完全同步"，反而假**。解法：2# 槽的 `video.currentTime` 加一个固定偏移（如 +11.3s），或对 2# 做水平镜像。
12. **iOS Safari** 对 `VideoTexture` + `playsinline` 有额外限制 —— demo 主要在 PC 大屏，先不投入。

## 6. 创新点

1. ★★ **泡沫视频 ↔ 品位联动（看得见的因果）**
   从**正在播的这一帧视频**里实时算泡沫特征 → 驱动品位预测。
   屏幕上的品位不再是数据集里的静态值，而是"**这一帧泡沫算出来的**"。这是把"AI 视觉分析"从标语变成机制。
2. ★ **泡沫流速** = 稠密光流均值
   浮选操作的关键工艺量。业界（BubbleCV）靠逐气泡跨帧跟踪，我们用光流均值就能拿到同量级的量，且**真的从视频算**，不是编的。
3. **分形维数**替代 `texture_energy`
   有文献支撑、可解释："泡沫纹理复杂度"是泡沫大小分布的间接度量。
4. **停机即冻结**
   设备停 → 泡沫不动 → 分割停止 → 该设备的实时特征不再更新（而不是继续吐假数）。
